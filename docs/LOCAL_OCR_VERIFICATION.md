# 端末内OCR検証記録

## 初回画面確認

開発URLの `/upload` を開いたところ、画面が空白表示となった。ブラウザコンソールにはエラーが出力されていない。Service Workerの旧キャッシュまたは開発サーバー再読込状態を切り分け、OCRワーカーを起動する前に画面表示を復旧してからOCR実行を検証する。

その後にDOMを確認した結果、Service Worker・Cache Storageはいずれも未登録で、アップロード画面の内容はReact DOMに正常に描画されていた。最初のスクリーンショット取得時の描画待機による表示上の問題であり、画面実装そのもののエラーではないことを確認した。

個人情報を含まない日本語SVGテスト画像をアップロード画面へ投入し、選択済みファイル名が画面に反映されることを確認した。OCR実行状態が継続して表示されなかったため、次にブラウザの実行時エラーを確認する。

実際のファイルアップロードでもSVGはブラウザの画像デコーダーで読み取れず、「The source image could not be decoded」となった。これはOCR入力としてのSVG非対応によるもので、画像/PDF向けの主要形式であるPNG/JPEG/HEICとPDFの挙動とは分けて扱う。個人情報を含まないPNGテスト画像を生成し、実画像で検証を続ける。

PNGテスト画像を実際に選択すると、「向きを補正して読み取り中」と表示され、ローカルOCRワーカーの初期化処理（initializing api）が開始された。画像ファイル選択からOCR開始までのワークフローが動作している。

OCR処理は完了し、元画像を添付した下書き確認画面へ自動遷移した。日本語OCR結果には文字間スペースと丸数字が含まれ、初回の見出し抽出では下書き項目に反映されなかったため、改行を保持したまま文字間スペース・丸数字を正規化する処理とユニットテストを追加した。修正後は新規作成フローで再検証する。

修正後にPNGテスト画像を再処理した結果、アクシデント種別、発生日時（2026-08-12 14:30）、発生場所（デイルーム）、対象者（A.K.）、事象概要、要因、対応状況が自動下書きへ正しく反映された。元画像とOCR抽出テキストもIndexedDBの下書きに保存され、確認・修正画面へ遷移した。

90度回転した横向きPNGテスト画像についても、端末内OCRの開始と向き補正処理表示を確認した。OCR完了後の自動下書き内容を継続して確認する。

初回の90度テストで十分な向き補正結果が得られなかったため、0/90/180/270度の全候補を端末内で認識し、認識信頼度と日本語文字数から最適な向きを選択する処理を追加した。修正後の横向きテストを開始し、認識中の進捗表示を確認した。

4方向判定後の90度回転テストでは、アクシデント種別、発生日時、発生場所、対象者、事象概要、要因、対応状況が正しく下書きに反映された。続けて180度回転した逆さま画像を選択し、同じ端末内OCRの認識処理が開始された。

180度回転した逆さまテスト画像でも、アクシデント種別、発生日時、発生場所、対象者、事象概要、要因、対応状況が正しく下書きに反映された。画像の0/90/180/270度補正を確認できたため、次に同じ日本語画像を含むスキャンPDFのページ単位OCRを検証する。

日本語テスト画像を含むスキャンPDFを選択すると、端末内OCRワーカーの初期化が開始された。PDF.jsでページを描画し、画像OCRへ渡すフローの完了結果を続けて確認する。

スキャンPDFの1ページを端末内で画像化・OCRした結果、アクシデント種別、発生日時、発生場所、対象者、事象概要、要因、対応状況が下書きへ正しく反映された。元PDFとPDFページ由来のOCR抽出テキストも端末内の報告書へ保存されている。

GitHub Pages相当の `/incident-triage-app/` サブパスで静的PWAを起動した。Service WorkerのPrecacheに日本語言語データ（`jpn.traineddata.gz`）、OCRコア、OCRワーカーが格納されていることを確認し、初回オンライン起動後のOCRもオフラインで利用できる構成になっている。

静的配信サーバーを停止した後でも、GitHub Pages相当のサブパスURLからOCR対応PWAが起動した。続けてPNGテスト画像を選択すると、キャッシュ済みの日本語言語データを読み込むOCR処理が開始された。

配信停止中でもOCR処理は完了し、アクシデント種別、発生日時、発生場所、対象者、事象概要、要因、対応状況を含む下書きが作成された。Service Workerキャッシュだけで、OCRワーカー・日本語言語データ・IndexedDB保存が動作することを確認した。

画像デコードに失敗するSVGを選択した場合、エラーメッセージと選択済みファイル名が表示され、「同じファイルで再試行」ボタンが表示された。画像とPDFの共通OCRフローで、ファイルを再選択せずに同じ入力を再実行できる導線を確認した。
