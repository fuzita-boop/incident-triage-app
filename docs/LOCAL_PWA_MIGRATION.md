# 完全ローカルPWA移行方針

## 目的

本アプリは、報告書本文、添付された画像・PDF、分析結果、月次集計を端末上のブラウザ内に限定して保存する。静的サイトとして配信するコードには利用者データを含めず、アプリの通常利用時にログイン、サーバーDB、クラウドストレージ、外部AI APIを必要としない。

## 保存先と通信境界

| 対象 | 保存先 | 通信 | 備考 |
| --- | --- | --- | --- |
| 報告書、下書き、確定状態、分析結果 | IndexedDB | なし | ブラウザ・端末ごとに分離される |
| 添付画像・PDF | IndexedDBのBlob | なし | ファイルを外部へアップロードしない |
| バックアップ | ユーザーが指定する端末内のZIPファイル | なし | 利用者が暗号化済み領域へ保管する |
| アプリ本体 | GitHub Pagesの静的ファイル | 初回取得と更新確認時のみ | 利用者データは含めない |

## 既存クラウドデータの保全

移行開始時点で、クラウド側には17件の報告書が存在する。内訳は確定済み3件、下書き14件であり、すべてに元画像またはPDFへの参照がある。

移行前には、旧アプリから報告書JSONと添付ファイルをひとつのバックアップZIPとして端末へダウンロードする。新PWAではこのZIPを選択してIndexedDBへ復元できる。バックアップは個人情報を含み得るため、GitHubリポジトリへ追加せず、施設の暗号化済み保管先または暗号化済み外部媒体で管理する。

旧Manusプロジェクトの実行環境では、次の一回限りのコマンドで現在のクラウドDBと添付ファイルをローカルPWA互換ZIPへ書き出せる。

```bash
node scripts/export-legacy-backup.mjs /安全な保存先/incident-triage-legacy-backup.zip
```

出力したZIPは、新PWAの「バックアップ・復元」画面から復元する。ZIPには個人情報を含み得るため、GitHubへのコミット、メール添付、平文のクラウド共有フォルダへの配置を行わない。

## 運用上の注意

ブラウザのサイトデータ削除、ブラウザの初期化、端末の紛失・故障、プライベートブラウズの終了は、ローカルデータの消失につながる可能性がある。確定前後を問わず、定期的にPWAのバックアップ機能でZIPを書き出し、端末とは別の暗号化済み保管先に保存する。

## 機能の置換方針

外部AIによる画像・PDF解析は完全オフラインでは実行できないため、ローカルPWAでは添付を端末内に保持したうえで、報告内容を手入力・編集する方式に置き換える。集計、インシデント/アクシデント別の分析、フィッシュボーンの要因整理、月次A4レポート出力は、IndexedDBに保存したデータからブラウザ内で計算する。

## GitHub Pages

Viteのベースパスをリポジトリ名に合わせて設定し、GitHub Actionsが静的ビルド成果物をGitHub Pagesへ配置する。クライアントルーティングはGitHub Pagesのサブパスと直接アクセスに対応する。GitHub Pagesの公開設定は、リポジトリ設定で公開元をGitHub Actionsに変更する必要がある。
